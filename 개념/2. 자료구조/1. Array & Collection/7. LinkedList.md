**LinkedList :**
데이터를 노드(Node)라는 단위로 나누어 저장하고, 각 노드가 서로 연결되어 있는 형태의 컬렉션



\----------------------------------------------------------------------------------------------



**-구조 :**



Node1 ⇄ Node2 ⇄ Node3



Node :
연결 리스트를 구성하는 각각의 데이터 단위
단순히 데이터만 가지고 있는 것이 아니라 다른 노드와 연결하기 위한 정보도 가지고 있다.



\----------------------------------------------------------------------------------------------



**-데이터 조작 :**



*생성 :*
LinkedList<자료형> 변수명 = new();



*추가 :*

linkedList.AddFirst(데이터); ->

맨 앞에 데이터를 추가


linkedList.AddLast(데이터); ->

맨 뒤에 데이터를 추가


LinkedListNode<자료형> node = linkedList.Find(데이터);
linkedList.AddAfter(node, 데이터); ->

특정 노드 뒤에 데이터를 추가


linkedList.AddBefore(node, 데이터); ->

특정 노드 앞에 데이터를 추가





*삭제 :*
linkedList.Remove(데이터);


ex)
10 ⇄ 20 ⇄ 30
->
10 ⇄ 30


삭제된 값이 사라지며 앞이랑 전 노드가 연결됨


linkedList.RemoveFirst(); ->

첫 번째 노드를 제거



linkedList.RemoveLast();->

마지막 노드를 제거




*노드 검색 :*


LinkedListNode<자료형> node = linkedList.Find(데이터);



First, Last :
첫번째 노드와 마지막 노드
linkedList.First.Value
linkedList.Last.Value



*개수 :*
numbers.Count

\-특징 :


1. 인덱스로 바로 접근 불가능 
메모리상에서 연속적으로 붙어 있지 않고,

서로의 위치 정보만 갖고 있기 때문(다음 노드가 어디 있는지만 알고 있음) ->

특정 위치의 데이터를 바로 접근하기보다는 노드를 따라 이동하면서 탐색하는 방식



2\. 중간에 데이터를 삽입하거나 삭제할 때 연결 관계만 변경하면 된다.
반면 배열이나 리스트에서는 추가 작업이 필요 ->

중간 삽입/삭제가 매우 빈번한 상황에서는 LinkedList가 유리



3\. 노드를 이미 알고 있다면 삽입/ 삭제가 효율적이지만,
원하는 노드를 찾는 것 자체는 느릴 수 있음



\----------------------------------------------------------------------------------------------



**-다른 자료구조들과의 차이 :**



List



List : 

구조 : 동적으로 관리되는 배열 기반

인덱스 접근 : 매우 빠름

중간 삽입/삭제 : 데이터 이동 필요



LinkedList :

구조 : 노드들의 연결

인덱스 접근 : 직접 직원X

중간 삽입/삭제 : 노드 연결 변경



Stack, Queue

Stack, Queue : 대아터 처리 순서 위함

LinkedList : 데이터를 연결된 노드 구조로 관리 위함
