**Stack :**
프로그램이 실행되는 동안 함수 호출과 지역 변수 등의 정보를 임시로 저장하는 메모리 영역

Stack은 메서드 실행에 필요한 정보를 관리하는 메모리 영역이고, 참조형 변수는 객체 자체가 아니라 객체를 가리키는 참조를 저장한다.



\----------------------------------------------------------------------------------------------



**-Stack Frame :**

메서드가 호출되면 해당 메서드의 실행에 필요한 정보가 Stack Frame이라는 형태로 Stack에 쌓인다.





ex)

void Main()

{

&#x20;   int a = 10;

&#x20;   Test();

}

void Test()

{

&#x20;   int b = 20;

}



Main() 호출

&#x20;     ↓

Main Frame -> a = 10

Test() 호출

&#x20;     ↓

Test Frame ->  b = 20

Main Frame -> a = 10

&#x20;     ↓

Main Frame -> a = 10



Test()가 끝나면 Test의 Stack Frame이 제거됨.

메서드 호출 → Stack에 쌓임 → 메서드 종료 → 제거



\----------------------------------------------------------------------------------------------



**참조(Reference)와 값형과의 관계 :**



ex)

class Player

{

&#x20;   public int HP;

}



void Test()

{

&#x20;   Player player = new Player();

&#x20;   player.HP = 100;

}



Stack -> player 참조

Heap -> Player 객체, HP = 100



player 변수는 객체를 참조하고 있는거지 객체 자체가 아니다.



값형 =/= Stack

참조형 =/= Heap 



Player player = new Player()

new Player()는 실제로 생성된 객체고, player는 그 객체를 가리키는 변수



\----------------------------------------------------------------------------------------------



**-Heap과의 관계 :**



변수/객체 ->

Satck(지역 변수 등) 참조 --> Heap 객체



변수가 사라진다고 해서 반드시 객체가 즉시 사라지는 건 아니다.

C#에서는 더 이상 객체를 참조하는 곳이 없어지면 Garbage Collector(GC)가 나중에 해당 객체를 정리한디.



\----------------------------------------------------------------------------------------------



**-LIFO :** 

메서드 흐름 구조와 잘 맞ㅇ음

Main() -> A -> B -> C

메모리 : C → B → A → Main 순서
